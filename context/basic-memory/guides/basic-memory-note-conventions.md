# Basic Memory Note Conventions

Guidelines for creating and managing notes in the fluent-toolkit Basic Memory project.

## Folder Structure

- `features/` - Feature documentation (not prefixed with issue numbers, may span multiple issues)
- `plans/` - Task management and implementation plans (see [Plan Notes for Complex Tasks](guides/plan-notes-for-complex-tasks))
- `guides/` - How-to documentation and usage instructions
- `technologies/` - Technical documentation and architecture
- `research/` - Cached research results
- `meetings/` - Meeting notes

## Note Naming Conventions

**IMPORTANT**: These naming conventions apply **only to plan notes**. Plans are complex tasks or issues that benefit from persistent definitions with checklist steps that can be updated over time. Plans can exist locally or be mirrored as GitHub/Jira issues based on user preference.

**Other note types** (features, guides, technologies, research, meetings) should use descriptive titles without issue numbers and are independent of issue tracking.

### Plan Note Titles

**Default (No Issue Assigned)**:

- Use descriptive Title Case
- No issue number prefix
- Examples:
  - `"Add Scoped Environment Variable Management"`
  - `"Dynamic Version Resolution"`
  - `"Tart VM Testing Infrastructure"`

**With Issue Number** (when assigned):

- Prefix with issue tracker notation
- GitHub: `#NNN:` (zero-padded to 3 digits)
- Jira: `PROJECT-NNN:` (also zero-padded)
- Examples:
  - `"#018: Add Scoped Environment Variable Management"`
  - `"#001: Add Claude Code Installation Checks"`
  - `"PRJ-042: Implement Custom Plugin System"`
- **Zero-padding rationale**: Ensures alphabetical file sorting matches numeric order

### Plan Note Filenames

For plan notes only, filenames should be the **kebab-cased version of the title**:

| Title                          | Filename                        |
| ------------------------------ | ------------------------------- |
| `"Add Feature Name"`           | `add-feature-name.md`           |
| `"#018: Add Feature"`          | `018-add-feature.md`            |
| `"PRJ-042: Add Plugin System"` | `prj-042-add-plugin-system.md`  |
| `"Dynamic Version Resolution"` | `dynamic-version-resolution.md` |

**Important** (for plan notes):

- ❌ DON'T use `issue-018-add-feature.md` (old convention)
- ✅ DO use `018-add-feature.md` (when GitHub/Jira issue assigned)
- ✅ DO use `add-feature.md` (plan exists locally, no issue yet)

**For other note types** (features, guides, etc.):

- ✅ Always use descriptive names: `dynamic-version-resolution.md`, `development-workflow.md`
- ✅ Never include issue numbers (these notes span multiple issues or are independent)

### Permalinks

Permalinks are auto-generated by Basic Memory to match the filename (without extension):

| Filename             | Permalink               |
| -------------------- | ----------------------- |
| `add-feature.md`     | `plans/add-feature`     |
| `018-add-feature.md` | `plans/018-add-feature` |

**When using Basic Memory MCP**:

- Basic Memory automatically generates filenames and permalinks from title
- **Auto-kebab-casing**: When `BASIC_MEMORY_KEBAB_FILENAMES=true` (default for FTK projects):
  - Title `"Add Feature"` → filename `add-feature.md` → permalink `plans/add-feature`
  - Special characters and spaces automatically converted to hyphens
  - Issue prefixes preserved: `"#018: Add Feature"` → `018-add-feature.md`
- **Don't manually specify filename or permalink** - both are auto-generated from title

## Frontmatter Requirements

### Plans

```yaml
---
title: "Add Feature Name" # or "#018: Add Feature Name" when assigned
type: plan
# permalink auto-generated as: plans/add-feature-name
tags:
  - feature-area
  - technology
  - type
---
```

### Features

```yaml
---
title: "Feature Name"
type: feature
# permalink auto-generated as: features/feature-name
tags:
  - related-tags
related-to:
  - "[[#018: Implementation Plan]]" # link to implementing issues
---
```

### Guides

```yaml
---
title: "Guide Topic"
type: guide
# permalink auto-generated as: guides/guide-topic
tags:
  - documentation
  - how-to
---
```

## Workflow

### Creating a New Plan

1. **Initial Creation** (no issue yet):

   ```
   Title: "Add Feature Name"
   Filename: add-feature-name.md
   ```

2. **After Issue Creation**:

   ```
   Title: "#018: Add Feature Name"
   Filename: 018-add-feature-name.md
   ```

   - Use `move_note` to rename
   - Update title in frontmatter
   - Update internal heading

3. **Format with Prettier**:
   ```bash
   npx prettier --write context/basic-memory/plans/018-add-feature-name.md
   ```

### Updating Existing Notes

When an issue number is assigned:

1. Update the title: `"Add Feature"` → `"#018: Add Feature"`
2. Rename file: `add-feature.md` → `018-add-feature.md`
3. Basic Memory updates permalink automatically
4. Format with Prettier

## Best Practices

### DO

- ✅ Format all notes with Prettier after creation/editing
- ✅ Include observations and relations sections
- ✅ Update titles/filenames when issue numbers are assigned
- ✅ Use descriptive, searchable titles
- ✅ Link related notes with `[[note-title]]` syntax
- ✅ Keep filenames in kebab-case
- ✅ Use status emojis in plans (📌 ⏳ ✅)

### DON'T

- ❌ Use `issue-N-` prefix in filenames (old convention)
- ❌ Include file extensions in permalinks
- ❌ Use spaces or special characters in filenames
- ❌ Forget to format with Prettier
- ❌ Leave stale status or outdated information
- ❌ Create markdown files outside Basic Memory

## Migration from Old Convention

**Old Convention** (deprecated):

```
Filename: issue-018-add-feature-name.md
Title: "Issue 18: Add Feature Name"
```

**New Convention**:

```
Filename: 018-add-feature-name.md (or add-feature-name.md if no issue yet)
Title: "#018: Add Feature Name" (or "Add Feature Name" if no issue yet)
```

**Migration Steps**:

1. Identify notes using old `issue-N-` pattern
2. Use Basic Memory `move_note` to rename
3. Update title in frontmatter
4. Update internal heading
5. Format with Prettier

## Tools

```typescript

move_note(project, identifier, destination_path);
```

```bash

npx prettier --write context/basic-memory/plans/[filename].md

npx prettier --write context/basic-memory/plans/*.md
```
